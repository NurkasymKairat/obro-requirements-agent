# Агент проверки требований

Консольный ИИ-агент статического ревью документа требований до начала разработки.
Читает документ (PDF, Markdown, TXT, DOCX), выделяет требования, проверяет каждое и набор целиком
по ISO/IEC/IEEE 29148:2018 (п. 5.2.5, 5.2.6) и IEEE 830-1998 (п. 4.3) и пишет отчёт на русском.

## Установка

Нужен Python 3.11 или новее. Проверьте версию:

```
python3 --version
```

Если версия ниже 3.11 (на macOS системный `python3` — 3.9), поставьте новый Python
(macOS: `brew install python@3.12`, Windows и Linux: https://www.python.org/downloads/)
и в команде создания окружения ниже вызывайте его явно: `python3.12` вместо `python3`.
Со старым Python `pip install` падает с ошибкой «No matching distribution found for google-genai».

macOS, Linux:

```
python3 -m venv .venv
source .venv/bin/activate
python --version
pip install -r requirements.txt
```

`python --version` внутри окружения должен показать 3.11 или новее.

Windows (PowerShell):

```
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если PowerShell отвечает, что выполнение сценариев отключено, перед активацией выполните
`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` (действует только в текущем окне).

Все команды ниже выполняются из корня репозитория с активированным окружением.
Если окружение не активировано, вместо `python` пишите `.venv/bin/python` (Windows: `.venv\Scripts\python`).

## Ключ

1. Откройте https://aistudio.google.com/apikey и войдите аккаунтом Google.
2. Нажмите «Create API key» и скопируйте ключ. Бесплатного тарифа достаточно.
3. Создайте файл настроек из шаблона: `cp .env.example .env` (Windows: `copy .env.example .env`).
4. Откройте `.env` и впишите ключ после знака равенства: `GEMINI_API_KEY=ваш_ключ`.

Файл `.env` лежит в корне репозитория и не попадает в git. Остальные строки `.env` можно не трогать:
пустое значение означает значение по умолчанию (исключение — списки запасных моделей, см. ниже).

## Запуск

```
python -m agent docs/requirements.md reports/report.md
```

Первый аргумент — проверяемый документ (`.pdf`, `.md`, `.txt`, `.docx`), второй — путь к отчёту.
Ход прогона печатается в консоль.

## Веб-интерфейс

Тот же агент в браузере: загрузка документа, ход прогона по проходам, текст документа с подсветкой
цитат и замечания карточками с фильтрами. Ключ берётся из того же `.env` и остаётся на сервере.

Нужен Node.js 20 или новее (только для сборки фронта). Один раз:

```
pip install -r requirements-web.txt
cd web && npm ci && npm run build && cd ..
```

Запуск — одна команда, API и собранный фронт:

```
python -m api
```

Откройте http://127.0.0.1:8000. Кнопка «Открыть пример» показывает сохранённый прогон
(`api/demo/sample_other.md` и `api/demo/sample.json`) без вызова модели. Другой пример задают
переменные `WEB_DEMO_DOC` (документ) и `WEB_DEMO_RESULT` (`report.json` прогона по этому документу;
`.md` с тем же именем рядом — отчёт для скачивания).

Режим разработки, с перезагрузкой при правках, в двух терминалах:

```
python -m api --reload
cd web && npm run dev
```

Фронт откроется на http://localhost:5173, запросы `/api` уходят на порт 8000.

- Одновременно идёт один прогон. Загруженный файл удаляется после прогона, состояние хранится в памяти
  сервера и сбрасывается при перезапуске.
- Файлы: PDF, Markdown, TXT, DOCX до 10 МБ.
- `WEB_PIPELINE=stub` — заглушка вместо модели: проигрывает проходы сохранённого примера
  (`stub-incomplete` — то же с оборванным прогоном). Для проверки интерфейса без ключа.
- `WEB_TITLE` — название продукта в интерфейсе (по умолчанию «Проверка требований»).
- Оформление (цвета, шрифты, размеры, пропорции экрана) задано в `web/src/styles/_tokens.scss`.
- Тесты API: `python -m pytest api/tests`.

## Где отчёт

- `reports/report.md` — отчёт: паспорт прогона, главное (до пяти самых критичных дефектов), нарезка
  требований, проверка каждого требования, проверка набора, сводка, итог.
- `reports/report.json` — те же данные в машиночитаемом виде.

Папка `reports/` создаётся сама.

## Сколько вызовов модели делает прогон

Документ целиком передаётся в каждый вызов. Для `docs/requirements.md` (67 требований) прогон делает
9 вызовов:

- 1 — нарезка документа на требования;
- 5 — проверка каждого требования (по 16 требований в вызове);
- 1 — сверка требований с критериями приёмки;
- 1 — сверка частей документа между собой;
- 1 — ревью найденного: слияние дублей, калибровка степени, оспаривание, поиск пропусков (последний проход).

Проверки без модели (пустые поля шаблона, методы и коды HTTP, типы полей) вызовов не делают.
Повторы при 503 и 429 добавляют вызовы сверх этого.

Прогон занимает около 5 минут, 9 вызовов модели; дольше всего идут сверки и ревью, где модель рассуждает. Независимые вызовы (пачки проверки требований и сверки) идут параллельно, не больше `AGENT_CONCURRENCY` одновременно (по умолчанию 3); ревью — после них.
Ход прогона печатается по вызовам: модель, время, токены входа, выхода и рассуждения. В конце печатается
итог — число вызовов, суммарные токены, время прогона по часам (от старта до записи отчёта) и
отдельно сумма длительностей вызовов: вызовы идут параллельно, поэтому сумма может быть больше времени прогона.
Те же цифры записываются в паспорт
отчёта и в `report.json` (`wall_seconds`, `calls_seconds`; по каждому проходу — `stages`).

## Если Gemini отвечает 503, 429, 402, 403 или не отвечает

**503** («model is currently experiencing high demand») — временная перегрузка модели на стороне Google,
с ключом и агентом всё в порядке. Агент делает до трёх повторов с нарастающей паузой (2, 4, 8 с), затем
переходит на следующую модель из `GEMINI_FALLBACK_MODELS`.

**429** — превышен лимит тарифа.
- Лимит запросов в минуту: агент ждёт столько, сколько просит сервис, и повторяет. Если 429 повторяется
  часто, уменьшите `GEMINI_RPM` в `.env`.
- Дневная квота модели: агент сразу переходит на следующую модель из `GEMINI_FALLBACK_MODELS`
  (квота у каждой модели своя).

**Запрос завис (тайм-аут)** — модель не ответила за отведённое время: 90 с для проходов с минимальным
рассуждением (`AGENT_TIMEOUT`), 360 с для проходов с рассуждением medium или high (`AGENT_TIMEOUT_THINKING`).
Это временный сбой, но каждая попытка стоит целый тайм-аут, поэтому повтор на той же модели один и без
паузы, затем сразу переход на следующую модель из `GEMINI_FALLBACK_MODELS` для всех последующих вызовов.
Ответ 504 обрабатывается так же. Три повтора остаются для быстрых отказов: 503, 429 по минутному лимиту, обрыв сети. У OpenAI действуют те же две настройки.

**403** с текстом «The Gemini API free tier is not available for this project» — в этом проекте Google
недоступен бесплатный тариф. Создайте ключ в новом проекте AI Studio под личным аккаунтом Google либо
включите оплату, впишите ключ в `.env` и запустите ту же команду. Агент останавливается сразу, без повторов и
без перехода на запасные модели: ошибка относится ко всему проекту.

На бесплатном тарифе gemini-3.8-flash бывает перегружена; агент сам переключается на запасную модель,
отчёт при этом может содержать меньше замечаний. Модель каждого прохода указана в паспорте отчёта.

**402** — закончился баланс платного аккаунта. Агент останавливается с сообщением о балансе: переход на
другую модель не поможет, баланс общий. Пополните баланс и запустите ту же команду.

Переход на запасную модель виден в консоли и в паспорте отчёта: там указано, какая модель отвечала на
каждом проходе. Если прогон оборвался (все модели недоступны, закончился баланс, сбой прохода), отчёт всё
равно записывается, но помечается как неполный: в паспорте и в итоге указано, какие проходы не выполнены,
вердикт не выносится, код выхода не 0.

## Если прогон прервался

Ответы модели кешируются в папке `CACHE_DIR` (по умолчанию `.cache/llm`). Повторный запуск той же
команды продолжает с последнего успешного вызова: готовые ответы берутся из кеша без новых запросов.
Ответ берётся из кеша, только если он получен от той же модели с теми же параметрами генерации: смена
модели или бюджета рассуждения даёт новые вызовы. Чтобы прогнать заново с нуля, удалите папку кеша.

## Как сменить модель

В `.env`:

```
GEMINI_MODEL=gemini-3.8-flash
GEMINI_FALLBACK_MODELS=gemini-3.6-flash,gemini-3.5-flash
GEMINI_THINKING_BUDGET=2048
```

Доступные ключу модели и их лимиты видны в Google AI Studio. Запасные модели перечисляются через запятую.
Пустое значение `GEMINI_FALLBACK_MODELS=` отключает переход на запасные модели.
Рассуждение и лимит ответа задаются по проходам атрибутами `THINKING` (`off` | `low` | `medium` | `high`; `off` и `low` — минимальный уровень модели) и `MAX_OUTPUT_TOKENS`: нарезка и проверка каждого требования — `off`, сверки и ревью — `high`; `GEMINI_THINKING_BUDGET=0` переводит все проходы в `off`.

## Другой провайдер

Чтобы работать через OpenAI, задайте в `.env` строки `LLM_PROVIDER=openai` и `OPENAI_API_KEY=...`.
Модель задаётся в `OPENAI_MODEL`, запасные — в `OPENAI_FALLBACK_MODELS`, глубина рассуждений — в `OPENAI_REASONING_EFFORT` (по умолчанию `medium`).
Кеш, повторы и переход на запасную модель работают так же, как у Gemini.

## Все настройки

Полный список переменных с пояснениями — в `.env.example`. Переменная окружения, заданная в оболочке,
важнее строки в `.env`. Если переменная записана в `.env` дважды, действует последняя строка.

## Коды выхода

| Код | Значение |
| ---: | :--- |
| 0 | Полный прогон, отчёт записан |
| 1 | Внутренняя ошибка агента |
| 2 | Ошибка настроек или входного файла: нет ключа, файл не найден, неподдерживаемый формат |
| 3 | Все модели недоступны (503, квоты): отчёт записан как неполный, запустите позже |
| 4 | Сбой одного из проходов: отчёт записан как неполный, вердикт не вынесен |
| 5 | Закончился баланс аккаунта (402): отчёт записан как неполный, пополните баланс |
| 6 | Проекту Google недоступен бесплатный тариф Gemini (403): отчёт записан как неполный, нужен ключ из нового проекта AI Studio или оплата |
| 130 | Прервано пользователем (Ctrl+C) — повторный запуск продолжит из кеша |

Для подробной диагностики внутренней ошибки запустите с переменной `AGENT_DEBUG=1`.
